## Why it is false: the change of coordinates is AFFINE, and the floors DECREASE with degree

The dictionary itself (`C53b.lean`, landed) is exactly what the BLOCKED record described, and it
is *true*:

```
monicPoly a  =  Φ₂ ^ μ₂  +  ∑_{i < n} 𝔠_i · X^{a'(i)} Φ′^{b(i)} Φ₂^{j(i)}
```

with `deg (X^{a'} Φ′^{b} Φ₂^{j}) = j·D₂ + b·D′ + a' = i` exactly, and each such monomial monic.
So in raw coordinates

```
a_i  =  𝔠_i  +  ∑_{i' > i} γ_{i,i'} · 𝔠_{i'}  +  Δ_i ,        Δ := Φ₂^{μ₂} − X^{n} ,
```

`γ ∈ O`, `deg Δ < n`. That is "unipotent in the x-degree filtration" — and it does **not** imply
what the intended proof needs, for two independent reasons.

**(R1) The map is affine, not linear.** The translation is `Δ = Φ₂^{μ₂} − X^{n}`, which does not
depend on `a` at all. RAW-BOX always contains the zero class (witness `a = 0`, `addVal 0 = ⊤`).
DIGIT-BOX contains the zero class only if the two-key digits of `X^{n}` itself clear the floors
inside the window — i.e. only if `X^{μ₂D₂}` enters the tower-entry locus. **C.50's landed SPLIT
says it does not:** `E₂_gt_xfloor : T.D₂ * (T.e₂ * F.h) < T.E₂`, i.e. `dv₂(x^{D₂}) = D₂e₂h < E₂`.
See the general argument below.

**(R2) Even the linear part does not preserve the box, because the floors run the wrong way.**
A unitriangular map preserves a product box `∏ᵢ 𝔪^{mᵢ}` when `m` is **non-decreasing** in the
index — the pollution `∑_{i' > i} γ 𝔠_{i'}` must be at least as deep as slot `i`. But
`budgetSlot` is non-**in**creasing in `i`: `budgetFloor T μ₂ j a b` decreases when `j` grows and
decreases when `slotOffset T a b = a·e₂h + b·u₂` grows, and increasing `i` does exactly one of
those. So higher-degree slots are the *least* constrained and leak downwards. Numerically, in
the instance below, `𝔠 = (0, π²)` is in the digit box (`m₀ = 4`, `m₁ = 2`) yet its linear image
`(π³, π²)` is not in the raw box (`v(π³) = 3 < 4`).

## The general refutation (every tower datum, every `μ₂ ≥ 1`)

Ingredients, all corpus-internal:

* **(a)** `budgetFloor_le_iff` (C.52, **landed**): `budgetFloor T μ₂ j a b ≤ v ↔ μ₂E₂ + 1 ≤
  gridWeight T v a b j`, where `gridWeight T v a b j = e₁e₂·v + slotOffset T a b + j·E₂`.
* **(b)** C.50's transcribed scope note for `gridWeight` (`EFF.GENTOW1.08`): on the locus the
  weight is a **lower bound** for the `dv₂` of the evaluated monomial. Only this direction
  (`gridWeight ≤ dv₂`) is used.
* **(c)** `dv₂` is a valuation with `dv₂(π) = e₁e₂`, `dv₂(x) = e₂h`, `dv₂(Φ₂) = E₂`.
* **(d)** `E₂_gt_xfloor` (C.50, **landed**): `D₂·e₂h < E₂`.

Argument. Suppose the zero class lies in DIGIT-BOX at window `N`. Its witness `a` has every
`aᵢ ∈ 𝔪^N`, so `monicPoly a ≡ X^{n} (mod 𝔪^N·O[X])`; `dev` is `%ₘ`/`/ₘ` by *monic* divisors,
hence commutes with reduction, so every two-key digit of `monicPoly a` is congruent mod `𝔪^N` to
the corresponding digit of `X^{n}`. Therefore for every slot

```
min (budgetFloor T μ₂ j a' b) N  ≤  addVal (𝔠_{j,a',b}(X^{n})) .
```

By **(a)** every slot with `𝔠 ≠ 0` then has `gridWeight T (addVal 𝔠) a' b j ≥ μ₂E₂ + 1`, and by
**(b)+(c)** each corresponding monomial `𝔠·x^{a'}Φ′^{b}Φ₂^{j}` has `dv₂ ≥ μ₂E₂ + 1`; slots with
`𝔠 = 0` contribute `dv₂ = ⊤`. Summing,

```
dv₂ (X^{n} − Φ₂^{μ₂})  ≥  μ₂E₂ + 1 .
```

But by **(c)+(d)**, `dv₂(X^{n}) = μ₂·D₂·e₂h < μ₂E₂ = dv₂(Φ₂^{μ₂})` for `μ₂ ≥ 1`, so there is no
cancellation and `dv₂(X^{n} − Φ₂^{μ₂}) = μ₂·D₂·e₂h < μ₂E₂ + 1`. Contradiction.

Hence the zero class is in RAW-BOX and not in DIGIT-BOX, and

> `TriangularDigitRead T μ₂ N` is FALSE for every `T`, every `μ₂ ≥ 1`, and every
> `N ≥ N₀(T, μ₂) := 1 + addVal (𝔠_slot(X^{μ₂D₂}))` at an obstructing slot (finite, because the
> obstructing digit is nonzero).

The one step above that is corpus **intent** rather than a landed theorem is **(b)** — C.50's
header deliberately says `gridWeight` "asserts no relation to any valuation". That is why this
record also carries a fully explicit numeric instance, which needs none of (b)–(d).

## The explicit numeric instance (`N₀ = 2`)

Parameters: `e₁ = f₁ = h = 1` (so `D′ = 1`), `e₂ = 2`, `f₂ = 1`, `u₂ = 3`, `μ₂ = 1`. All
structure fences hold: `F.hcop = Coprime 1 1`; `T.hcomp : 2 ≤ e₂f₂ = 2`;
`T.hcop = Coprime 3 2`; `T.hfloor : e₂·D′·h = 2 < 3 = u₂`. Derived: `D₂ = D′·e₂f₂ = 2`,
`E₂ = e₂f₂u₂ = 6`, `n = μ₂D₂ = 2`, `d = e₁e₂ = 2`. Take `O` with residue characteristic `≠ 2`
(e.g. `O = ℤ_p`, `p` odd) and `Φ′ = F.key = X + π`.

`C.47`'s `natDegree_cLift_lt` gives `deg (cLift T s) < D′ = 1`, so `cLift T 0` is a **constant**
and `Φ₂ = Φ′² − cLift T 0 = X² + 2πX + (π² − cLift T 0)`. Hence `Φ₂.coeff 1 = 2π` exactly.

Floors (`budgetSlot T 1 i = budgetFloor T 1 (i/2) (i%2%1) (i%2/1)`, so slot `i` is `(j,a',b) =
(0,0,i)`):

| `i` | `slotOffset T 0 i` | `tgt = 1·E₂ − w` | `budgetFloor` |
|---|---|---|---|
| `0` | `0` | `6` | `(6+2−1)/2 + [6%2=0] = 3 + 1 = 4` |
| `1` | `u₂ = 3` | `3` | `(3+2−1)/2 + [3%2=0] = 2 + 0 = 2` |

Digits of `f = monicPoly a = X² + a₁X + a₀`: `dev Φ₂ f 0 = f − Φ₂ = (a₁ − 2π)X + (a₀ − π² +
cLift T 0)`, and with `Φ′ = X + π` of degree 1,

```
𝔠_{0,0,1} = dev Φ′ (f − Φ₂) 1 |coeff 0 = a₁ − 2π ,
𝔠_{0,0,0} = dev Φ′ (f − Φ₂) 0 |coeff 0 = a₀ − π a₁ + π² + cLift T 0 .
```

Take `N = 2` and `c = 0`.

* **RAW-BOX ∋ 0**: `a = 0` gives `addVal 0 = ⊤ ≥ 4, 2`.
* **DIGIT-BOX ∌ 0**: a witness needs `a₀, a₁ ∈ 𝔪²` and `addVal (a₁ − 2π) ≥ 2`. Writing
  `a₁ = π² t`, `a₁ − 2π = π(π t − 2)`, and `2` is a unit, so `addVal (a₁ − 2π) = 1 < 2`.

So the iff fails at `c = 0` for every `N ≥ 2`. (The same slot shows the sets differ, not merely
the witnesses: at `N = 5` both sides have `q⁴` classes — `towerFreeCount T 1 5 = (5−4)+(5−2) = 4`
— but DIGIT-BOX is the coset `a₁ ≡ 2π (mod 𝔪²)` and RAW-BOX is `a₁ ≡ 0 (mod 𝔪²)`.)
